1 · 왜 필요한가

JSON 구조는 맞는데, 내용이 그 장소의 것이 아니에요

아래는 비짓제주 API가 실제로 돌려준 항목이에요. 필드 이름도 형식도 정상이라 코드는 아무 오류 없이 화면에 그려요. 그런데 이름은 오름인데 실제로는 농업회사법인이고, 시 라벨은 주소와 다른 시를 가리켜요.

"title":"목화오름"
"region":"제주시"실제는 서귀포시
"area":"제주시내"실제는 안덕면
"addr":"제주 서귀포시 안덕면"
"cat":"관광지"오름이 아니라 목화·아마 농사를 짓는 패션 브랜드
✓ JSON 형식 검사는 통과

행사 쪽도 같아요. 민속자연사박물관 특별전 본문에 「2026. 10. 13.(금)」이라고 적혀 있지만, 2026년 10월 13일은 화요일이에요.

이런 오류는 형식 검사로는 절대 안 잡혀요. 다른 칸과 비교하거나, 바깥의 다른 출처와 비교해야 보여요. 그 일을 선생님 PC에서 미리 해 둔 거예요.

2 · 선생님 PC에서 한 일

세 증인의 투표, 그다음 웹에서 확인

먼저 한 장소의 위치를 세 가지로 따져요. 셋 중 둘이 맞고 하나만 다르면 그 하나를 틀린 칸으로 지목해요. 그다음 Claude가 웹을 검색해서 공식 페이지·기사로 다시 확인하고, 근거 URL을 남겨요.

원본 사이트 두 곳은 검색에서 막아 뒀어요. 원본으로 원본을 확인하면 아무 의미가 없으니까요. 근거가 없거나 출처끼리 다르면 지어내지 않고 「확인 불가」로 둬요.

4 · 네 사이트에서 일어나는 일

요청마다 실시간 값과 「검증할 때 본 값」을 비교해요

대조하는 코드는 api/_apply.js에 있어요. 핵심은 세 줄이에요.

5 · 네가 할 일

덮어쓰고, 배포하고, 헤더 하나만 확인

  1. 받은 폴더의 파일을 프로젝트에 같은 경로로 덮어쓰기처음엔 전부, 그다음부터는 api/_corrections.js 하나.
  2. 배포평소처럼 git push, 또는 vercel --prod. 환경변수를 새로 넣을 필요는 없어요.
  3. 개발자 도구 → Network → /api/visitjeju 또는 /api/event 응답 헤더 확인 
    X-Data-Corrections: verified=15; applied=11; hidden=0; upstream-fixed=0; stale=0
    verified = 검증됨, applied = 고쳐서 보여준 칸, upstream-fixed = 원본이 이미 고쳐진 칸 (숫자는 예시).
  4. stale이 0보다 크면 선생님께 알려 주기검증한 뒤 원본 API가 바뀐 항목이에요. Vercel 로그에 항목 번호가 찍혀 있어요. 다시 검증해서 새 파일을 줄게요.
